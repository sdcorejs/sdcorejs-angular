# SdLicenseService

**Type**: Service (Angular `@Injectable`)
**Class**: `SdLicenseService`
**Provided in**: `'root'`
**Import path**: `@sdcorejs/angular/services/license`
**Status**: **DEPRECATED — dormant, removed in release `1.8`**

## Deprecation notice (read first)

`@sdcorejs/angular` is a public MIT package and no component in it enforces a license any more — the
9 components that used to `extends SdBaseSecureComponent` dropped the inheritance (CHANGELOG entry
#21). `SdLicenseService` and `SdBaseSecureComponent` are kept only so existing subclasses keep
compiling; **both are `@deprecated` and will be removed in release `1.8`**. Do not wire new code to
them.

Because both are still exported, any consumer could `extends SdBaseSecureComponent` and get
`enforceLicense()` executed in the constructor. That path used to **throw** as soon as the app ran on
any non-localhost host without a `licenseKey` — a hard production crash for something the package no
longer uses. The unconfigured case is now a **no-op** (a one-line `console.warn` in dev builds only).

Decision, explicitly: *no `licenseKey` configured ⇒ the license gate is OFF*. Only a hostname that
fails an **explicitly configured** key list still throws, because that is a gate the consumer opted
into on purpose.

## One-line purpose
Domain-binding license check that hashes the current hostname (with a built-in salt) and compares
against `licenseKey` values from `SD_CORE_CONFIGURATION`; throws on unauthorized domains, bypasses
verification on loopback hosts, and stays inert when nothing is configured.

## When to use
- Nothing new. The gate is dormant and scheduled for removal; use application-level authorization.

## When NOT to use
- For per-feature flags / role-based authorization — use a real authZ service. This is a domain-level kill switch, not a permission system.
- For production secrets — the salt is in client code; this guards against casual misuse, not a determined attacker.
- For new code of any kind — see the deprecation notice.

## Public API

### `enforceLicense(): void`
**@deprecated — removed in release `1.8`.** Throws if the hostname failed an explicitly configured
key list during construction. No-op when no `licenseKey` is configured, and no-op on non-browser
platforms. Safe to call repeatedly.

```typescript
enforceLicense = (): void;
```

**Throws**: `Error('[Security] Unauthorized usage of UI Lib on domain: <hostname>')` — only when
`licenseKey` **is** configured and the hostname matches neither an exact nor a wildcard key.

## Configuration / DI tokens

### `SD_CORE_CONFIGURATION` — provides `licenseKey`
The service reads `coreConfiguration.licenseKey` (a single hash string or an array of hash strings) from `@sdcorejs/angular/configurations`.

```typescript
// app.config.ts
providers: [
  { provide: SD_CORE_CONFIGURATION, useValue: <ISdCoreConfiguration>{
    licenseKey: ['NTA0NDM2NjE3OTk0c2lnbmVk', 'LTYzMjMyOTkyMDdzaWduZWQ='],
    // ... other core config
  }},
]
```

Each key is generated by hashing `<domain> + SALT` with the service's internal algorithm (a 32-bit string hash, then `btoa(hash + 'signed')`). Keys are normally produced by a build-time tool the lib vendor provides — do not try to compute them at runtime.

### `DOCUMENT` / `PLATFORM_ID` — where the hostname comes from
The hostname is read through the injected `DOCUMENT` (`document.defaultView.location.hostname`), not
from the `window` global. Two consequences:

- **SSR-safe**: on a non-browser platform (`isPlatformBrowser(PLATFORM_ID) === false`) the service
  skips verification entirely and reports valid, so merely injecting it during server rendering no
  longer throws `ReferenceError: window is not defined`. The real check runs on the client after
  hydration.
- **Testable**: a spec can supply the hostname by overriding `DOCUMENT`, with no need to redefine
  `window.location` (which Chrome forbids).

## Behavior notes
- **Loopback bypass** is an **exact** match: `localhost`, `127.0.0.1`, `[::1]`, `::1`, or a genuine
  `.localhost` subdomain (`api.localhost`, RFC 6761). It used to be the substring test
  `domain.includes('localhost')`, which approved `localhost.attacker.tld` and `notlocalhost.com` —
  i.e. anyone able to pick a hostname could bypass the whole check.
- **Verification flow**:
  1. Non-browser platform → valid, stop.
  2. Loopback host → valid, stop.
  3. No `licenseKey` configured → valid (gate off), dev-mode warning, stop.
  4. Exact match: `hash(hostname + SALT)` against the key list.
  5. Wildcard fallback: progressively shift subdomains and try `hash('*.' + suffix + SALT)`. Stops at TLD+1 (won't match `*.com`).
  6. No match → throw.
- An empty `licenseKey` array counts as "not configured" (step 3).
- **Salt** is a hard-coded constant in source: `'angular-core-976e2fa6f8b44dadbc63f87b057a331f'`.
- **Side effect at construction**: the constructor calls `#verify()`; with a configured key list on a
  mismatching host, injecting the service alone throws. `enforceLicense()` rethrows the same condition.
- **Security caveat**: the hash is a non-cryptographic 32-bit string hash (`(hash << 5) - hash + char`). Do not treat keys as secrets — they only block trivial domain swaps.

## Examples

### 1. Boot-time guard with `APP_INITIALIZER`
```typescript
import { APP_INITIALIZER } from '@angular/core';
import { SdLicenseService } from '@sdcorejs/angular/services/license';

providers: [
  {
    provide: APP_INITIALIZER,
    useFactory: (lic: SdLicenseService) => () => lic.enforceLicense(),
    deps: [SdLicenseService],
    multi: true,
  },
],
```

### 2. Configure single-domain license
```typescript
{ provide: SD_CORE_CONFIGURATION, useValue: {
  licenseKey: 'NTA0NDM2NjE3OTk0c2lnbmVk',     // hash for 'app.customer.com'
}}
```

### 3. Configure wildcard subdomain
```typescript
// Generated from '*.customer.com'
{ provide: SD_CORE_CONFIGURATION, useValue: {
  licenseKey: ['LTYzMjMyOTkyMDdzaWduZWQ='],
}}
// Now app1.customer.com, app2.customer.com all pass via wildcard fallback.
```

### 4. Guard a feature lazily
```typescript
class PremiumFeature {
  constructor(private lic: SdLicenseService) {}
  open() {
    this.lic.enforceLicense();   // re-check before showing
    // ... open premium UI
  }
}
```

## Testing

### In unit / integration tests
On `localhost` (Karma / Jest default) the loopback bypass fires and the service is safe to inject.
No mock needed for localhost-only tests.

```typescript
// Simplest — just inject: loopback bypass always passes in Karma
TestBed.configureTestingModule({});
const service = TestBed.inject(SdLicenseService);
expect(() => service.enforceLicense()).not.toThrow();
```

To exercise non-localhost paths, override `DOCUMENT` with the hostname you want. Do **not** try to
redefine `window.location` — Chrome forbids it, which is exactly why the earlier specs silently
skipped:

```typescript
TestBed.configureTestingModule({
  providers: [
    SdLicenseService,
    { provide: DOCUMENT, useValue: { defaultView: { location: { hostname: 'app.example.com' } } } },
    { provide: SD_CORE_CONFIGURATION, useValue: { licenseKey: '<pre-computed hash>' } },
  ],
});
expect(() => TestBed.inject(SdLicenseService)).not.toThrow();
```

⚠️ Override `DOCUMENT` at the `TestBed` level **only** for service-only specs. If the spec also calls
`TestBed.createComponent(...)`, the DOM renderer needs the real document — build the service in its
own `Injector.create({ ... })` and provide the resulting instance instead (see
`components/base/src/base-secure.component.spec.ts`).

Simulate SSR with `{ provide: PLATFORM_ID, useValue: 'server' }`; the service reports valid without
reading a hostname.

To completely skip license enforcement in tests, provide a stub:

```typescript
{ provide: SdLicenseService, useValue: { enforceLicense: () => {} } }
```

### Spec file
`projects/sdcorejs-angular/services/license/src/license.service.spec.ts`

Covers **25 specs, all executing** (the file previously had 9 `pending()` specs that never asserted):
- loopback bypass: instantiation, `enforceLicense()` no-op, no-config tolerance, repeat call safety
- exact loopback matching: `localhost`, `127.0.0.1`, `[::1]`, `api.localhost`, plus regressions for `localhost.attacker.tld` and `notlocalhost.example.com`
- non-browser platform: valid without reading a hostname, even with a mismatching key configured
- unconfigured gate: no throw, `enforceLicense()` no-op, dev-mode warning present / absent
- enforcement: exact hash match, array key match (hit and miss), wildcard match, deep wildcard, mismatch throw, error message content, 2-part hostname, empty key array

## Anti-patterns
- Do NOT build new features on this service — it is removed in `1.8`.
- Do NOT ship the SALT or generated keys as if they were security tokens — they're an obfuscation, not authentication.
- Do NOT call `enforceLicense()` inside hot loops — it just re-checks a boolean, but the throw is uncaught and will crash the zone.
- Do NOT add `localhost` to your `licenseKey` list — it already bypasses, and the dev banner won't show.
- Do NOT compute keys in app code with `btoa(...)` of arbitrary strings — the vendor's hash algorithm must match exactly.
- Do NOT rely on "no config ⇒ crash" as a safety net — an unconfigured gate is intentionally OFF.
