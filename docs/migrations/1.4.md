# Migration guide for release suffix 1.4

Release suffix `1.4` maps to `19.1.4`, `20.1.4`, and `21.1.4`. The first number continues to match the application's Angular major. This release is mostly additive, but several hardened defaults require review.

## Upgrade checklist

1. Install the `1.4` package for the matching Angular line.
2. Compile direct class consumers/tests because migrated signal members are no longer plain fields or RxJS `EventEmitter`s.
3. Review every mutation passed to `SdApiService`; mutation deduplication and retry are now opt-in.
4. Move concurrent loading code to returned `SdLoadingRef` handles or `run()`.
5. Verify cache/storage namespace, version, custom key and serializer configuration before reading production browser data.
6. Exercise responsive layout during resize, not only at bootstrap.
7. Run application keyboard/screen-reader smoke tests for any newly adopted picker, breadcrumb, data-state, progress or audit UI.

## API requests

GET requests deduplicate by default. POST, PUT, PATCH and DELETE do not. This prevents two identical writes from being collapsed accidentally.

```ts
const users = await api.get<User[]>('/api/users');

await api.patch<User>('/api/users/42', update, {
  signal: abortController.signal,
  retry: { attempts: 2, delayMs: 250 }, // ignored for a mutation unless mutations is true
});
```

Only opt a mutation into deduplication/retry after confirming the endpoint is idempotent:

```ts
await api.put<Result>('/api/idempotent-import/42', payload, {
  dedupe: true,
  retry: { attempts: 2, mutations: true },
});
```

- Response generics default to `unknown`; specify `<T>` or validate the response.
- `autoCache` is deprecated as a dedupe alias. Use `dedupe`; keep `cacheOption` for persistent response caching.
- Per-caller `AbortSignal` cancellation does not cancel another owner of the same shared GET.
- Retry is bounded, cancellation-aware, and off by default.

## Loading ownership

Balanced `start(selector)` / `stop(selector)` remains compatible. The preferred API retains ownership explicitly:

```ts
const ref = loading.start('#editor');
try {
  await save();
} finally {
  ref.close();
}
```

Or use:

```ts
await loading.run(() => save(), '#editor');
```

Multiple refs may overlap; the overlay and `aria-busy` remain until the final owner closes. Repeated `close()` calls are safe. SSR returns a closed no-op ref while `run()` still executes the task.

## Cache, storage and persistence

Cache/storage now share a versioned graph serializer and envelope. `Date`, `Map`, `Set`, `BigInt`, `undefined`, special numbers, shared references and cycles round-trip. Unsupported values throw instead of being silently corrupted by JSON cloning.

```ts
const settings = storage.create<Settings>('settings', {
  namespace: 'portal',
  version: 2,
});

const reports = cache.create<Report[]>('reports', {
  type: 'session',
  ttlMs: 60_000,
  namespace: 'portal',
  version: 2,
});
```

- Existing pre-1.4 JSON values are dual-read and migrated after validation.
- Namespace, version, args/default presence, TTL and serializer identity participate in the effective key. Changing them intentionally creates a new partition.
- `SD_CACHE_CONFIG` is now consumed. Verify custom `convertKey`, remote callbacks and global serializer settings.
- `SD_STORAGE_CONFIG.key` now receives a versioned base key; avoid double-prefixing.
- Use cache `snapshot()` when a stored `undefined` differs from a miss.
- Call cache `release()` and storage/cache `destroy()` for dynamic handles on owner teardown.
- Browser storage unavailable/quota/corruption paths are contained; SSR continues in memory.

The new low-level entrypoint `@sdcorejs/angular/services/persistence` is public for custom adapters/serializers. Custom implementations must validate untrusted text and preserve bounded failure behavior.

## Form connector and controls

`ɵsdFormControlConnector` consolidates parent registration, dynamic name/parent changes, model/control synchronization, validation state and destroy cleanup. It is exported with an Angular-private `ɵ` prefix for library control authors; normal application templates do not call it.

Existing `[(model)]`, `[form]`, `name`, disabled, readonly and viewed bindings remain. Run form lifecycle tests if application code directly instantiates controls or changes form/name dynamically.

New public form entrypoints:

- `@sdcorejs/angular/forms/time`
- `@sdcorejs/angular/forms/time-range`
- reusable masks from `@sdcorejs/angular/forms/input`
- `@sdcorejs/angular/forms/entity-picker`
- `@sdcorejs/angular/forms/tree-select`

Time values use canonical `HH:mm` strings rather than `Date`, so no timezone conversion is required.

## Responsive layout

`SdViewportService` observes viewport changes through one injected, SSR-safe source. `SdLayoutResponsiveService` and `SD_LAYOUT_VIEWPORT` remain compatibility adapters, including custom providers.

Applications that previously calculated mobile/desktop once at startup should consume `width`, `height`, `breakpoint`, `mobile`, `tablet`, or `desktop` signals. Server rendering resolves to a deterministic desktop state unless a custom viewport provider is supplied.

## PDF preview and workflow UI

`SdPreviewPdf` now implements continuous rendering, print adapters, outline navigation, bounded thumbnail/search work, loading/error states and deterministic resource cleanup. Browser capabilities are injected; unsupported actions are omitted or inert on SSR.

New workflow/operations entrypoints:

- `SdBreadcrumb`, `SdDataState`
- `SdUnsavedChangesService` with route/FormGroup/close adapters
- `SdTaskService` and `SdJobProgress`
- `SdAuditDiff`

These APIs are standalone/OnPush, localized where they own copy, and expose semantic keyboard/ARIA behavior. Backend mapping stays in typed callbacks/adapters rather than the components.

## Signal inputs and outputs

Template binding names remain stable. Direct class consumers/tests must use Angular signal contracts after a migrated member:

```ts
fixture.componentRef.setInput('value', nextValue);
const currentValue = fixture.componentInstance.value();
const observed: unknown[] = [];
const subscription = fixture.componentInstance.sdChange.subscribe(value => observed.push(value));
subscription.unsubscribe();
```

Do not call RxJS-only `EventEmitter` APIs such as `pipe()`, `complete()` or `error()` on a signal output.

## Deprecations

| Deprecated API                 | Replacement                                                                     |
| ------------------------------ | ------------------------------------------------------------------------------- |
| `SdApiOption.autoCache`        | `SdApiOption.dedupe`                                                            |
| `SD_API_CONFIGURATION`         | `SD_API_CONFIG`                                                                 |
| Generic legacy cache callbacks | globally safe `unknown` callbacks, or temporary `adaptLegacySdCacheCallbacks()` |

No package has been pushed, tagged or published by this migration document; it describes the code prepared for the single `1.4` release unit.
