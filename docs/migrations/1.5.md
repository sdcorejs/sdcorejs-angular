# Migration guide for release suffix 1.5

Release suffix `1.5` maps to `19.1.5`, `20.1.5`, and `21.1.5`. The first number continues to match the application's Angular major. This release extends Layout V1/V2/V3 with optional account actions and navigation presentation changes; existing required configuration remains compatible.

## Upgrade checklist

1. Install the `1.5` package for the application's Angular major.
2. Exercise the configured Layout version at desktop width and below `mobileBreakpoint`.
3. Configure only the optional account actions that the application supports and authorize each destination in application code.
4. Give menu groups and leaves stable `id` values before adopting V2 primary menus or V3 Pinned/Recent state.
5. Verify account labels, notification counts, keyboard focus, Escape handling and mobile scroll restoration.
6. Select the exact installed package version in the Showcase and verify the version-pinned API document before rollout.

## Account menu configuration

`signout` remains required. `changePassword`, `updateProfile`, `setting`, `notification` and `userInfo.role` are optional. Layout renders an action only when its callback is present.

```ts
import { ApplicationConfig, inject, signal } from '@angular/core';
import { Router } from '@angular/router';
import { ISdLayoutConfiguration, SD_LAYOUT_CONFIGURATION } from '@sdcorejs/angular/modules/layout';

const unreadNotificationCount = signal(6);

export const appConfig: ApplicationConfig = {
  providers: [
    {
      provide: SD_LAYOUT_CONFIGURATION,
      useFactory: () => {
        const router = inject(Router);

        return {
          mobileBreakpoint: 1024,
          sidebar: {
            version: 2,
            interaction: 'click',
            primaryMenuIds: ['workspace', 'reports', 'settings'],
            pin: { enabled: true },
          },
          userInfo: {
            fullName: 'Demo User',
            role: { text: 'Operator', icon: 'badge' },
          },
          signout: () => router.navigate(['/signout']),
          changePassword: () => router.navigate(['/account/change-password']),
          updateProfile: () => router.navigate(['/account/profile']),
          setting: () => router.navigate(['/account/settings']),
          notification: {
            count: unreadNotificationCount,
            action: () => router.navigate(['/notifications']),
          },
        } satisfies ISdLayoutConfiguration;
      },
    },
  ],
};
```

The action order is Profile, Settings, Notifications, Change password and Sign out. Notification counts accept a number, Angular `Signal` or RxJS `Observable`; values are normalized to a non-negative integer, the badge is hidden at zero and display is capped at `99+`. The notification action remains available when the count is zero.

Layout does not fetch account data, navigate to application pages or enforce permission rules for account actions. Keep those responsibilities in the consumer callbacks.

## V2 and V3 navigation

- V2 accepts at most three valid `primaryMenuIds`. Missing slots are filled from the remaining visible root menus; overflow is available from More.
- V3 keeps Pinned and Recent destinations as stable menu keys. A persisted collapsed preference takes precedence over `defaultCollapsed`.
- V2 and V3 desktop/mobile search use the same Soft-pill presentation while preserving their existing placeholder, `autoId`, accent-insensitive filtering and parent-owned search state.
- The compact V2 account trigger and collapsed V3 drawer center the avatar. Collapsed V3 hides the brand block and keeps the expand control.
- Mobile V2 and V3 keep identity and sign-out on the same account row; the remaining configured actions stay in the action list.

Pinned and Recent entries are shared between sidebar versions. V2 active/locked group state and V3 collapsed state remain version-scoped. Do not read the UUID-backed storage records directly; use `SdLayoutNavigationStateService` or `SdLayoutStorageService`.

## Responsive and embedded layout behavior

`<sd-layout>`, `<sidebar-mobile-v2>` and `<sidebar-mobile-v3>` now use block-level hosts. This prevents their full-height shells from aligning to an inline text baseline when rendered in the Showcase or a consumer container.

The public shell still uses the dynamic viewport and reserves mobile navigation space with `100dvh`. Mount one Layout as the application's top-level portal shell; do not nest it in a modal, drawer or widget. Test at a width strictly below the normalized `mobileBreakpoint` because the desktop/mobile pair switches live without a route reload.

## Version-pinned documentation

The Showcase reads `published-docs/versions.json` and exposes every published `1.2+` archive for Angular 19, 20 and 21. Static route shells use the same manifest-derived release list. This fixes 1.3/1.4 URLs being redirected to 1.2 and means 1.5 requires no source-code allowlist.

After the `v1.5` tag is successfully published, the release workflow collects the current 97-document source catalog into:

```text
docs/19.1.5/index.json
docs/20.1.5/index.json
docs/21.1.5/index.json
```

Each index links to immutable Markdown for that package version, including the complete Layout reference. The release PR intentionally does not pre-create `published-docs/*1.5`: archives are committed only after their matching npm packages have published successfully.

Before release, verify the collector without mutating the published archive:

```powershell
npm run collect-release-docs -- --patch 1.5 --date <YYYY-MM-DD> --out-root <temporary-directory>
```

Confirm that all three generated indexes have the same document count and that `modules/layout/sd-layout.md` is present in each archive.

## Compatibility summary

| Area                   | 1.5 behavior                                           | Consumer action                             |
| ---------------------- | ------------------------------------------------------ | ------------------------------------------- |
| Required Layout config | `sidebar`, `userInfo` and `signout` remain required    | No change                                   |
| Account extensions     | Role, profile, settings and notifications are optional | Add only supported callbacks                |
| Menu search            | Presentation is shared across V2/V3                    | Recheck custom visual overrides             |
| Mobile shells          | Custom-element hosts are block-level                   | Remove consumer baseline workarounds if any |
| Versioned docs         | Every published `1.2+` release is selectable           | Choose the exact installed version          |

No package has been pushed, tagged or published by this migration document; it describes the code prepared for the single `1.5` release unit.
