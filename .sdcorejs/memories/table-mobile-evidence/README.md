# sd-table mobile cards — review

Date: 2026-09-05. Scope: the user's approved mobile-card specification, amended by their compact-mobile layout feedback on PR #34. Canonical changes are in `versions/v19`; v20/v21/v22 are generated by `npm run sync`.

## Compact mobile sheets and selection

The user's latest review of commit `db065c8d7bf188c5e2bc7b1b4bfa0f8ea3b5dab7` supersedes the original plan and previous footer/selection layout. The immutable plan records the original feature; this record captures the newer user-directed correction on PR #34.

- One **Tools** footer button opens a titled `SdModal` bottom sheet containing the enabled reload, export, filter, sort and configuration tools. Filter/configuration close this sheet before opening their existing panel.
- Card commands open a separate `SdModal` bottom sheet titled **Row actions: <row label>**. Command groups, order, icons, disabled/hidden rules and callbacks retain their existing contracts.
- Only selection uses a contained, compact `SdQuickAction`: a highlighted numeric count, eligible direct actions, More when required, and a clear icon. It omits `selector.message` and every mobile page-selection checkbox. The accessible name/live region retain the full total/on-page summary.
- A 14px checkbox/radio graphic sits on a 24px circular surface centered over the top-right border corner. Its 40px touch target is reserved within the list padding. Row commands occupy a separate bottom-right target.
- `SdTableCommandHeaderDef`, such as **Add**, is centered above the cards. No mobile filter/sort/selection toolbar occupies the top of the table.

Regression checks cover the previous layout failures. A real keyboard test also reproduces and fixes opening a newly created modal before its title/dismiss bindings are rendered. Opening after render supplies the correct dismiss policy; Escape closes the row sheet without selecting or invoking a command. Overlay-scoped label layout keeps icons and text aligned with a 12px gap.

## Public API and example

- `SdTableRowMobileDefDirective<T>` and `SdTableRowMobileDefContext<T>` are exported from the table and components entry points.
- Optional `SdTableOption<T>.mobile.rowLabel(row)` supplies visible and accessible row labels. Fallback is a primitive `rowKey`, then a meaningful row ordinal.
- `SdQuickAction.contained` supports the action presenter inside the table's own scroll container.
- [Complete standalone OrdersComponent](orders.component.ts) is extracted verbatim from the [source component documentation](../../../versions/v19/projects/sdcorejs-angular/components/table/sd-table.md). It includes imports, typed data/options, the mobile template, row commands and an async bulk callback.

The bare `sdTableRowMobileDef` attribute works, but its `item` defaults to `any`. Use `[sdTableRowMobileDef]="tableOption"` for checked generic inference. The compiler check includes a deliberate nonexistent `Order` property and requires that compilation to fail.

## Decisions and behavior

The Core viewport service chooses one row renderer. Data, filters, sort, paginator, selection, identity and expansion remain in the same table instance. Resize does not fetch or reapply defaults. Eligibility is prepared by shared utilities before either renderer runs; it does not depend on desktop pipe side effects.

Active row commands and selected rows are independent. Each table owns its selection presenter and tools/command sheets; row commands use no QuickAction. Actions receive the existing row or full-selection payload, respectively. Promise callbacks block duplicates and preserve selection on either outcome; the consumer decides which successful rows to remove and when to reload. The documentation includes partial-success handling.

Shared page-selection APIs remain covered without a mobile page checkbox. Group headers, loaded/visible tree selection scope, custom slots, command headers, footer totals, filter, sort, paginator, export and drag handles retain their existing data contracts. A shared MatSort and paginator remain available even when the table starts directly on mobile.
