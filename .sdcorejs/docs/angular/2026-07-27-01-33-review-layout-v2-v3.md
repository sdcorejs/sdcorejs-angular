# Layout V2/V3 review and repair — 2026-07-27

## Request

Review the latest `feat/layout-navigation-polish` branch, repair the Layout V2/V3
findings, make release suffix 1.5 documentation-complete, then commit, push and
open a pull request.

## Root causes

1. `<sd-layout>`, `<sidebar-mobile-v2>` and `<sidebar-mobile-v3>` were inline
   custom-element hosts. Their `100dvh` children aligned to a text baseline and
   started 101 px above the 620 px Showcase preview, clipping V2 content and the
   V3 mobile topbar.
2. The Showcase selected only hard-coded `21.1.2`, `20.1.2` and `19.1.2`
   releases even though `published-docs/versions.json` already contained the
   immutable 1.3 and 1.4 archives.
3. The static route-shell generator duplicated the hard-coded release list, so
   future 1.5 routes would require another source change.
4. Release lint included raw generated Showcase sources and failed on generated
   changelog formatting.
5. Full Showcase tests still expected the pre-`f465b2c` registry state (84
   published documents and 12 local-only pages), while the runtime registry now
   exposes 97 published documents.

## Repairs

- Made the three Layout hosts block-level and added regression assertions in the
  canonical v19 specs, then synchronized v20/v21.
- Derived the Showcase release catalog from the published manifest for supported
  Angular majors and release suffixes 1.2 or newer.
- Made static route-shell generation use the same manifest-derived release set.
- Added future-1.5 coverage to the runtime catalog and route-shell generator.
- Excluded generated Showcase TypeScript from authored-source lint gates while
  retaining generator freshness tests.
- Updated stale registry and changelog assertions to mirror generated/runtime
  data.
- Added `docs/migrations/1.5.md`, README/npm README links, changelog entries,
  Layout technical documentation and Showcase documentation-site guidance.
