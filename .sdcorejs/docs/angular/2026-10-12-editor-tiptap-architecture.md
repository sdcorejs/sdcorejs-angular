# Technical architecture

`components/editor-engine` is an internal Angular secondary entrypoint shared by Editor/MiniEditor. It owns the full OSS schema, HTML import diagnostics, content lifecycle and Core toolbar/surface. Public consumers use component-owned options; Tiptap/ProseMirror objects are not implicit CK compatibility.

The secondary entrypoint is published for Angular packaging but excluded from the top-level components barrel; direct engine/surface imports are implementation API without a promised consumer compatibility contract. Component option and diagnostic types are explicitly re-exported at their normal Editor/Mini entrypoints. Mutable engine, upload queue, selection bookmark and generation state are strictly per component instance.

Engine receives source HTML and retains it until actual editing. Before enabling editing, sanitized DOM is compared to schema parse/serialize semantics. Supported formatting structures preserve attrs through explicit extensions. Unknown structures/attributes cannot be silently flattened: unsupported safe source mounts a safe read-only preview, returns original SAFE value through unedited getters, and reports diagnostics; paste rejects unsupported HTML atomically. Unsafe source remains in the caller's existing model/form without automatic mutation, but is never exported as safe HTML: getters/upload throw `SdEditorImportError`, and safe preview renders only the sanitized form. Sanitization is a separate boundary, applied before mounting and before emitting/exporting, using existing Core sanitizer plus a scoped safe CSS policy. Active embeds are rejected. No `bypassSecurityTrustHtml`.

All schema capabilities load for both toolbars, independent of visible controls. Basic/compact toolbar changes available actions only. Toolbar owns accessible CoreUI controls, selection bookmarks across popups and local focus restoration. An editor transaction updates Angular signals/ChangeDetectorRef without restoring focus when popup owns it. Composition delays emissions and external echoes never replay content.

Source→sanitized semantics must be checked separately BEFORE schema comparison; a removed safe attribute/unsupported CSS yields a blocking unsupported diagnostic, and safety removal yields unsafe diagnostic. Equal value echoes are ignored. A differing authoritative external write during composition is deferred to compositionend, immediately invalidates pending emissions/popup/upload generation, then replaces silently; it never merges into unfinished composition or emits the stale composed document.

Focus outputs preserve editable DOM focus/blur FocusEvent behavior (not composite focus); Editor blur marks touched and Mini blur invokes CVA touched. Toolbar/popup interactions may therefore emit editable blur as before. Immediate command restores editor focus. Popup Cancel/Escape restores its trigger; Apply restores mapped editor selection and focus; outside-click retains destination. Disable/destroy/external replacement invalidates stale bookmarks and must not move focus back.

Surface initializes only in browser after rendering and destroys engine/listeners/timers once. SSR renders an inert escaped preview without constructing Tiptap; client mounts after hydration. Parent components retain their existing form contracts and emission cadence. External writes are silent, reset source generation and cancel stale insertion/results; user edits are sanitized and trigger the established event/form path.

Upload manager owns File/object-URL lifecycle and snapshot identities rather than document positions. Only still-present temporary image IDs receive async replacements; removed/replaced documents and destroyed engine ignore results. Validate file count/size/signature/dimensions, result cardinality and URL. Deferred retry retains failed pending files; immediate queue respects batch/concurrency. Abort cannot cancel app callbacks unless supported, so no false cancellation claim.

Dependencies: exact aligned MIT Tiptap 3.31.4 packages (core, pm, starter-kit, extensions, table, text-style, image, text-align, subscript, superscript, mention, suggestion, markdown). Installed suggestion package requires peer `@floating-ui/dom ^1.0.0`; integration pins verified MIT `1.8.0` rather than leaving a runtime import unresolved under legacy peer installs. Verify installed tarball/transitive licenses before notice. Existing sanitizer reused, no new sanitizer dependency without justified gap. Exact versions and manifests/locks updated only by integration owner; v20–v22 generated via sync.

Stage A repair addendum: SSR counter uses standard HTML parsing instead of a tag/entity regex. `parse5@7.3.0` is MIT and its installed entity decoder is BSD-2-Clause. This version retains the existing Node compatibility floor; parse with `scriptingEnabled:false` to match DOMParser, find body and count UTF-16 text while excluding img/figure. Integration owns dependency/lock/notices and includes this addition in bundle measurement.

Composition state callback/output: engine `onCompositionStateChange(boolean)` → surface `compositionChange` → adapters. Begin notification pauses existing debounce/throttle without clearing upload state; preserve pending value and cadence deadline. Engine ends composition by processing current change or silent queued source, then emits false. Adapters queue change callbacks while composing and flush the latest pending value after false; source replacement/destroy cancels it. This covers timers that were scheduled before compositionstart.

PoC first proves round-trip/loss detection using actual browser parser and real Tiptap, then component TDD. Existing sanitizer fixtures, synthetic rich fixture with captions/merged tables/nested lists/attrs, malicious fixture, unknown node/attr and Markdown are separate cases with recorded origin. Browser/Angular behavior cannot be inferred from Node serialization alone.

## Exact internal/public contracts

- Shared entrypoint exports `SdEditorEngine`, library-owned `SdEditorEngineOptions`, `SdEditorImportDiagnostic`, `SdEditorImportError`, `SdEditorMentionItem`, `SdEditorMentionFeed`, plus `SdEditorSurface` for internal Angular composition. Public component options refer only to library-owned types. Components do not expose a fake CK constructor/instance/config.
- `SdEditorImportDiagnostic` has `code: 'unsafe-html'|'unsupported-html'|'markdown-loss'|'invalid-option'`, `path: string`, optional `tag`/`attribute`, and `detail: string` (developer detail, UI localizes by code). Engine `diagnostics` readonly array; callbacks `onDiagnostics(readonly diagnostics[])`, `onChange(string)`, `onFocus(FocusEvent)`, `onBlur(FocusEvent)`, `onStateChange()`.
- Engine options: `content?:string`, `format?:'html'|'markdown'`, `editable?:boolean`, `placeholder?:string`, `mentionFeeds?:readonly SdEditorMentionFeed[]` and callbacks. Constructor `(element: HTMLElement, options: SdEditorEngineOptions)`. Methods `setContent(value:string):void` (silent external replacement), `getContent():string`, `getHtml():string`, `setEditable(boolean):void`, `focus():void`, `destroy():void`, `insertMention({id,name,marker?}):void`, `getMentions():{id,name,marker}[]`. `editor` is real Tiptap instance for Core implementation; never claimed to be CK.
- Surface composition contract: selector `sd-editor-surface`; inputs `content` string default `''`, `format` html/markdown default html, `variant` full/compact default full, `editable` boolean default true, `placeholder` optional string, `mentionFeeds` optional readonly feeds, `uploadEnabled` boolean default false, `height`/`maxHeight` optional strings. Outputs `engineReady` SdEditorEngine, `change` string, `focus`/`blur` FocusEvent, `diagnostics` readonly diagnostics, `filesSelected` File[]. Engine is initialized browser-only after view render and destroyed by surface; component adapters must not double-own lifecycle. Component options updates configure placeholder/feed/editable through surface; engine-affecting schema options must recreate only with preserved source and diagnostics.
- Engine image manager boundary: `insertImage({src,alt?,id?,loading?,width?,height?}):void`, `activeImageSources():Set<string>`, `replaceImage(oldSrc, attributes):boolean`; async manager validates generation + still-present source before replacement. Component/surface file picker emits `File[]`; manager owner implements validation/upload, engine never calls app callbacks.
- Component diagnostics: Editor adds `sdImportWarning` output, Mini adds `importWarning`, each `readonly SdEditorImportDiagnostic[]`; preserve each component's existing output naming convention. Both expose readonly `importDiagnostics` state. No automatic value output during an import warning.
- Raw CK `Editor`, `editorConfig`, `onReady(ClassicEditor)` surfaces are removed with explicit breaking migration. Exported `EditorOption` / `SdMiniEditorConfig` become deprecated aliases of Core-owned engine options, with no plugins/licenseKey/CK methods; no fake compatibility. `MentionFeedObjectItem` becomes deprecated alias of Core-owned `SdEditorMentionItem`.
- API before/after: all Editor input names/aliases/types/defaults in inventory stay (option `{}`, height/maxHeight `250px`, strings/validator/form/key/autoId optional, booleanAttribute flags false, name UUID, model alias string `''`); outputs remain string and FocusEvent. `focusEditor` and `upload` stay; raw CK surfaces listed above removed. Mini required option decorator, value string `''`, boolean disabled signal false, maxEditorHeight, setContent/getContent/getHtmlContent/focusEditor/insertMention/getMentions and CVA method names stay; add setDisabledState and OnChanges synchronization. Mini outputs/callback names/payloads remain; generation prevents stale throttle callbacks after external write. Source contract timing remains debounce100ms and throttle500ms leading/trailing.
- Mention item `{id:string;name?:string;text?:string;data?:unknown}`; feeds `{marker:string;feed:readonly (string|SdEditorMentionItem)[] | ((query:string)=>readonly items[]|Promise<readonly items[]>);minimumCharacters?:number;dropdownLimit?:number}`. ID keeps caller identity; legacy HTML `data-id`/`data-marker` parsed losslessly. `itemRenderer` CK DOM hook is unsupported and diagnosed if present at runtime. Existing unused valueRender becomes deprecated; no invented behavior.
- Markdown remains optional OSS compatibility: input parses through verified OSS Markdown manager, unsafe HTML/links rejected; before export, Markdown→HTML→schema semantic comparison must prove no rich-node/attr loss. If Markdown cannot express the document, editing/conversion is blocked and original source remains; getter throws a diagnostic error instead of emitting lossy Markdown. HTML getters remain safe.

## Support and loss-detection matrix

- Editable: paragraph/headings1–6, blockquote/code block/hr/br, text marks strong/em/u/strike/code/sub/sup; nested ul/ol/li with start/type; text alignment and safe font/color/size; link href/title/target/rel; table rows/cells/headers with colspan/rowspan; image inline/block/figure and figcaption; legacy mention spans. Each capability requires a corpus proof before considered implemented.
- Preserve approved attrs: id/title/dir/lang/class, data-_/aria-_; table cell/span attrs, list attrs, image src/alt/loading/width/height/srcset/sizes, link attrs. Arbitrary attrs not explicitly supported must yield diagnostics. Class strings preserve data, but never override component interaction state; stored CSS selectors are not trusted.
- CSS allowlist: text-align, color/background-color, font-family/font-size/font-weight/font-style, text-decoration, vertical-align, white-space; table border/color/style/width/collapse/layout, padding; image width/height/max-width/float/display/margin variants. Parse each value using an inert browser style declaration, reject URL/functions/var()/expression/@/escape-based active values and unsupported properties. Unsupported safe CSS locks source rather than removing it silently. Safety removal is an unsafe diagnostic.
- Unsupported: active embeds/forms/SVG/MathML/raw-text (unsafe); dl/dd/dt or arbitrary safe structural wrappers/attrs not represented by schema (unsupported); captions/colgroups/table styles not implemented by a first PoC must lock source until proven. No blanket claim that sanitizer allowlist implies schema support.
- Comparison normalizes only documented equivalent parser wrappers (`tbody`) and tag aliases b/strong, i/em; all text, attributes and recognized style declarations are compared semantically. Empty paragraph serializer filler/trailing nodes are handled explicitly. A mismatch stays blocking. Diagnostics always retain source locator.

## Review repair contract: source, format and form delivery

Authoritative imports create a fresh native plugin/history baseline; equal echoes and representation changes preserve the current history. Initial import is not undoable. Source replacement accepts its target format atomically, including during composition, so unchanged source bytes can be reinterpreted in the explicitly supplied representation.

Internal engine callback onSourceChange(reason) distinguishes source, editable and format changes. Surface relays that reason and onFormatChange(value), where undefined means export is blocked by existing diagnostics. Mini cancels pending work for source/permission replacement, but pauses a format transition at its retained cadence deadline and resumes with the converted latest document. The engine document onChange remains silent for conversion. A blocked conversion keeps the pending live edit until a supported representation is restored or a new authoritative source supersedes it. Component public output names and payloads remain unchanged.

### HTML source tokens

The boundary uses the exported tokenizer from the already pinned `parse5@7.3.0` dependency to diagnose source tokens discarded by DOMParser. This replaces a custom regex lexer, which confused literal tag spelling inside bogus comments and closing-tag attributes with real elements. The tokenizer consumes HTML comment and quoted-attribute states; raw-text/RCDATA/script/plaintext modes are selected for their existing prohibited source categories. DOMParser and Core's sanitizer continue to own mounted markup.

Actual source comments, document types and closing-tag attributes are safe unsupported source: getters retain the original, and editing stays blocked until the application resolves the diagnostic. Core sanitizer `DROP_WITH_CONTENT` categories, including `use`, remain unsafe and fail through typed getters. The tokenizer export is marked internal by parse5, so its exact version stays pinned and dependency upgrades must pass the source-category/comment/getter/paste corpus. No token or parse5 type enters the public Editor/MiniEditor API.
