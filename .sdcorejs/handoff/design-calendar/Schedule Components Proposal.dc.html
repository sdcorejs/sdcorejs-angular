Bộ component lịch và lịch trình: đề xuất

Đề xuất 6 component cho 6 nghiệp vụ: lịch họp, lịch hẹn khách, đặt phòng, nghỉ phép và chấm công, tiến độ dự án, dòng thời gian hoạt động. Cả bộ dùng chung một lớp nền về thời gian, dữ liệu và kéo thả, chỉ dựa trên Angular CDK. Mục 04 là bản dựng sd-calendar có thể bấm thử.

01

Bối cảnh

Thư viện đã có đủ ô nhập ngày giờ và đã thống nhất múi giờ qua SdDateTimeService. Còn thiếu phần hiển thị nhiều sự kiện trên trục thời gian. Các component mới đặt trong components/. Option theo quy ước của sd-file-explorer và sd-table: nguồn dữ liệu và từng năng lực (tạo, dời) là một nhóm trong option.

Đã có: sd-date sd-datetime sd-date-range sd-time sd-time-range sd-chip-calendar sd-kanban sd-history SdDateTimeService

Tiến độ dự án
schedule-coreNền tảng dùng chung Không phải component hiển thị
Thời gianMọi phép tính ngày giờ đi qua SdDateTimeService, theo múi giờ cấu hình. Một ngày có thể dài 23 hoặc 25 giờ, nên không cộng 24h.
Ánh xạ dữ liệuConsumer map DTO sang SdCalendarEvent<T> (id, title, start, end, allDay, color, data) trong onLoad, như SdFileExplorerItem<T>.
Nguồn dữ liệuoption.dataSource.onLoad({ from, to, view, signal }) cho cả hai chế độ: client trả cả mảng, server gọi API theo khoảng. Request cũ bị huỷ khi đổi khoảng.

Lịch làm việcSD_CALENDAR_CONFIGURATION khai báo giờ làm việc theo thứ, ngày lễ (nghỉ hoặc chỉ đánh dấu), ngày đầu tuần. Input của từng component ghi đè được.
Dời và đổi giờoption.move = { movable, onMove } như sd-file-explorer; onMove trả boolean hoặc Promise, kèm AbortSignal. Kéo thả bằng Angular CDK, không thêm thư viện.

Mobile
  • Component dưới 600px: Tuần hiển thị như Ngày, kèm dải 7 ngày phía trên. Tháng chỉ còn chấm màu, chạm vào ngày để mở Ngày.
  • Chạm ô trống để tạo. Sự kiện cần chạm giữ 400 ms mới kéo được, để cuộn dọc không bị chặn.
  • Vùng chạm tối thiểu 44px cho dải ngày, nút điều hướng và nút chuyển chế độ.
  • Chi tiết sự kiện do consumer mở bằng bottom sheet; component phát sdSelect như desktop.
Sự kiện lặp
  • Chỉ hiện các lần nằm trong khoảng đang xem. Mỗi lần có id dạng {id}@yyyy/MM/dd theo ngày gốc, nên vẫn giữ id sau khi bị dời.
  • Dời hoặc đổi giờ một lần thì hỏi phạm vi: chỉ lần này, lần này và các lần sau, tất cả. Request mang scope; Huỷ hoặc Esc trả sự kiện về chỗ cũ.
Giờ làm việc, ngày lễ
  • Ngoài giờ làm việc, cuối tuần và ngày lễ nghỉ được tô nền nhạt nhưng vẫn tạo được sự kiện. Muốn chặn thì dùng option.create.creatable.
  • Ngày lễ có hai loại: off (chữ đỏ, tô cả cột) và observance (chỉ ghi tên, ví dụ 20/10).
  • Lưới mở ở đầu giờ làm việc; dòng đỏ là giờ hiện tại theo múi giờ cấu hình.
In, xuất
  • In theo chế độ đang xem: ẩn thanh công cụ, lưới vừa khổ A4 ngang, chỉ in trong giờ làm việc, nền màu đổi thành viền để in đen trắng vẫn phân biệt được.
  • Đợt 2: exportIcs(range) xuất các sự kiện trong khoảng, gồm cả quy tắc lặp.
06

API sơ bộ · sd-calendar

Import @sdcorejs/angular/components/calendar. Option theo quy ước của sd-file-explorer: nguồn dữ liệu và từng năng lực là một nhóm, callback đặt tên on<Action>, cờ năng lực là boolean hoặc predicate. Bản đầy đủ: design_handoff_sd_calendar/calendar.md.

interface MeetingDto { id: string; subject: string; from: string; to: string; allDay: boolean; room?: string; seriesId?: string; originalStart?: string; }

readonly option: SdCalendarOption<MeetingDto> = {
  dataSource: {
    onLoad: async ({ from, to, signal }) => {
      const rows = await firstValueFrom(this.api.meetings({ from, to }, { signal }));
      return rows.map(m => ({
        id: m.id,
        title: m.subject,
        start: m.from,                       // 'yyyy/MM/dd HH:mm:ss', ISO, epoch hoặc Date
        end: m.to,
        allDay: m.allDay,
        color: m.room ? 'info' : 'primary',  // Color của @sdcorejs/utils/models
        occurrence: m.seriesId ? { seriesId: m.seriesId, originalStart: m.originalStart! } : null,
        data: m,
      }));
    },
  },
  create: {
    creatable: range => !range.allDay,
    onCreate: range => this.openCreateDialog(range),   // trả SdCalendarEvent đã tạo, hoặc void khi huỷ
  },
  move: {
    movable: event => this.canEdit(event.data),
    onMove: async request => {
      await firstValueFrom(this.api.reschedule({ id: request.event.id, ...request.to, scope: request.scope }, { signal: request.signal }));
      return true;
    },
  },
};
