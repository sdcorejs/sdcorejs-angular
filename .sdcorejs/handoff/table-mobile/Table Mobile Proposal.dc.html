VÒNG 3 · API TEMPLATE

mobile.template: TemplateRef hoặc { layout, data: (item) => … }

Thay cho mobile.slots / mobile.layout ở 2b. layout nằm ngoài hàm, cố định cho cả bảng; data là hàm theo dòng, kiểu trả về theo layout. Bỏ layout nghĩa là 'card', cố định trong kiểu của thư viện; SD_TABLE_CONFIGURATION không có tùy chọn layout.

Đã chốt: layout ra ngoài hàm, giữ kiểu trả về của data qua union (3b). Đã chốt: có template thì không ẩn field theo Thiết lập; thẻ tự suy thì ẩn (3d).

Không khai báoBảng desktop như hiện tại. Bật SD_TABLE_CONFIGURATION.mobile.autoTemplate thì tự suy từ columns (2c), vẽ bằng card.
3bKiểu và ví dụ
export type SdTableMobileField<T> = NestedKeyOf<T>;
export type SdTableMobileText<T> =
  SdTableMobileField<T> | { text: string };

/** Phần chung của mọi layout. */
export interface SdTableMobileData<T> {
  title: SdTableMobileText<T>;
  subtitle?: SdTableMobileText<T>;
  /** field: cột phải có useBadge */
  badge?: SdTableMobileField<T> | SdBadgeData;
  fields?: SdTableMobileField<T>[];
}
export interface SdTableMobileCardData<T>
  extends SdTableMobileData<T> {
  /** Ô đầu lưới, chữ đậm */
  highlight?: SdTableMobileField<T>;
  /** Số ô trước nút Thêm. Mặc định 4 */
  maxFields?: number;
  trailing?: never;
}
export interface SdTableMobileListData<T>
  extends SdTableMobileData<T> {
  /** Giá trị bên phải dòng 1 */
  trailing?: SdTableMobileField<T>;
  highlight?: never;
  maxFields?: never;
}

export interface SdTableMobileDataContext {
  index: number;
  selected: boolean;
}
type DataFn<T, D> =
  (item: T, context: SdTableMobileDataContext) => D;

export type SdTableMobileTemplate<T> =
  | TemplateRef<SdTableRowMobileDefContext<T>>
  /** Bỏ layout = 'card' */
  | { layout?: 'card'; data: DataFn<T, SdTableMobileCardData<T>> }
  | { layout: 'list'; data: DataFn<T, SdTableMobileListData<T>> };

// SdTableOption<T>
mobile?: {
  rowLabel?: (row: T) => string;
  template?: SdTableMobileTemplate<T> | false;
};

// SD_TABLE_CONFIGURATION: không có layout
mobile?: {
  autoTemplate?: boolean;  // false
};
mobile: {
  rowLabel: row => row.code,
  template: {
    layout: 'card',
    // row: Order, kiểu trả về: SdTableMobileCardData<Order>
    data: row => ({
      title: 'code',
      subtitle: 'customerName',
      badge: row.locked
        ? { title: 'Đã khóa', color: 'error' }
        : 'status',          // cột status có useBadge
      highlight: 'total',
      fields: ['createdAt', 'warehouse', 'createdBy'],
    }),
  },
},
// Tách hàm ra ngoài: ghi kiểu trả về để IDE gợi ý
const orderCard = (row: Order): SdTableMobileCardData<Order> => ({
  title: 'code',
  badge: 'status',
  highlight: 'total',
});

template: { data: orderCard },   // bỏ layout = 'card'
// Lỗi lúc build
{ data: () => ({ title: 'cod' }) }
//  ✗ 'cod' không thuộc NestedKeyOf<Order>
{ layout: 'list', data: () => ({ title: 'code', highlight: 'total' }) }
//  ✗ highlight?: never ở SdTableMobileListData
{ data: () => ({ title: 'code', trailing: 'total' }) }
//  ✗ bỏ layout là 'card'; trailing?: never
{ layout: 'list', data: orderCard }
//  ✗ SdTableMobileCardData không gán được cho list

TypeScript không báo thuộc tính thừa trong object trả về từ arrow function, kể cả khi hàm có kiểu ngữ cảnh. Vì vậy mỗi kiểu data khai báo trường của layout khác là ?: never; thiếu bước này, highlight trong list vẫn build được.

Mỗi kiểu data khai báo trường riêng của layout khác là ?: never (3b). Layout mới: thêm một nhánh có layout bắt buộc, kiểu data extends SdTableMobileData, và bổ sung ?: never hai chiều. Khai báo đang có không phải sửa.

3dKiểm tra tên trường và hiển thị

Tên field được kiểm tra lúc build qua NestedKeyOf<T>. Điều kiện "badge phải là cột có useBadge" không kiểm tra lúc build được: columns có kiểu SdTableColumn<T>[], không giữ lại cột nào có useBadge. Phần này kiểm tra lúc chạy.

"Một phần" vì NestedKeyOf<T> chỉ biết field có trong T, không biết có column hay không. Cảnh báo chỉ ở isDevMode(), một lần cho mỗi bảng, field và loại lỗi. Ẩn hay hiện field không cảnh báo. Phần kiểm tra là một hàm thuần resolveMobileView(columns, layout, data), có spec riêng.

Quy tắc khác
  • data được gọi một lần cho mỗi dòng trong mỗi lần đổi dữ liệu (cache theo meta.id và dataRevision), không gọi theo change detection.
  • Giá trị đi qua cùng đường với ô desktop: transform, định dạng date / number, displayField của values / lazy-values, useBadge.
  • sdTableRowMobileDef giữ nguyên, tương đương template: TemplateRef. Khai báo cả hai thì directive được dùng, kèm cảnh báo.
  • Export SdTableMobileTemplate, SdTableMobileCardData, SdTableMobileListData, SdTableMobileDataContext từ @sdcorejs/angular/components/table.
VÒNG 2 · CHỐT HƯỚNG

Mobile: tách bố cục và nội dung

1e nên coi là một bố cục (khung dòng), không phải template. Bảng mobile có hai trục độc lập: bố cục do core vẽ, nội dung do template của consumer hoặc slots khai báo từ columns. Mọi bố cục đọc cùng một bộ slot, nên thêm bố cục sau này không đổi cách khai báo.

Bộ lọc: 1c hàng chip, chip đầu mở sheet 1b. Thẻ đợt 1: bố cục 'card' (1d) làm mặc định, nội dung slots (1f) khi không có template. Đợt 2: bố cục 'list' (1e), không phải khai báo gì thêm.

Hành vi thuộc khung chung, không thuộc bố cục: chọn dòng, ⋯ và sheet hành động, Chi tiết (expand), tree, reorder, nhãn aria, autoId. Bố cục chỉ quyết định vị trí của chúng.

  • Ưu tiên nội dung: sdTableRowMobileDef → mobile.slots → tự suy từ columns.

Ổn, nếu giữ 3 quy tắc
  1. Một bộ slot chung. Bố cục mới chỉ đọc slot đã có. Cần slot mới thì phải ghi rõ nó hiện ở đâu trong mọi bố cục cũ, nếu không thì rơi vào fields.
  2. Hành vi nằm ở khung chung; bố cục chỉ đặt vị trí. Không bố cục nào có cách chọn dòng hay mở hành động riêng.
  3. Giữ ít bố cục có sẵn (card, list). Nhu cầu riêng của một màn dùng template; template chạy trong khung của bố cục đang chọn.
Không nên

Mỗi bố cục một kiểu khai báo riêng, ví dụ union { type: 'list', primary, secondary } | { type: 'card', header, grid }:

  • Đổi bố cục phải viết lại khai báo.
  • Tài liệu, test và global config nhân theo số bố cục.
  • Không đặt được bố cục mặc định ở SD_TABLE_CONFIGURATION cho cả ứng dụng.
Câu ở vòng 1: mặc định nếu không có ý kiến khác
  1. Chip 1c: mọi externalFilters và cột có filter, theo thứ tự khai báo.
  2. Sheet một trường vẫn bấm Áp dụng, để không tải lại sau mỗi lần tick.
  3. Chọn khoảng ngày nhanh để đợt sau.
  4. Slots tự suy chỉ bật khi có mobile.slots hoặc mobile.layout; bật mặc định cho mọi bảng ở bản major tiếp theo.

03

Đề xuất và cần chốt

Bộ lọc: 1c để xem và sửa nhanh từng trường, chip đầu mở sheet 1b khi cần xem hết.

Thẻ: 1d làm khung mặc định, 1f khi không có template. 1e làm sau, bật bằng mobile.layout.

  1. Chip ở 1c: mọi trường đều lên chip, hay chỉ externalFilters và cột được đánh dấu?
  2. Sheet một trường: tick xong áp dụng ngay, hay vẫn bấm Áp dụng?
  3. Chọn khoảng ngày nhanh (Hôm nay, 7 ngày qua…) có làm trong đợt này không?
  4. 1f có bật mặc định cho mọi bảng chưa có template không?
